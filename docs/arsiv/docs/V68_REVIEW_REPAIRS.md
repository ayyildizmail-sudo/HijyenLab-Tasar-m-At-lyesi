1. `multi-logo-ui.js` forwards the entire `designIssue` call contract. Its default financial guard still requires approval; preview-only arguments cannot bypass missing, distorted, blocked, pending, orphaned or wrong-ground artwork guards.

Source SHA, operation and revision remain required. Reference acceptance is **not** semantic logo verification or selected-product application.
3. Reference source pixels remain unchanged, aspect-fitted with a persistent label. The normal summary and JPG include reference type and separate pricing-ground assumption. The source's colors are never replaced to match a pricing choice. Optional rear is a separately labeled idea preview, not a recovered reverse of the reference.
4. Unknown printing inks remain null by default in reference mode. An optional existing-field customer declaration of 1–3 colors may produce a clearly labeled scenario price; it is never called measured or physically confirmed. Source/product/rear/ground changes revoke this declaration; quantity changes do not. Current accepted uncertain artwork may show only a labeled product + freight subtotal. Unknown plate, tax and full total are null. Known fourth ink still blocks; gray/third-ink negatives remain. No threshold was relaxed to force NORI into two inks.
5. Unknown reference ground requires a normal white/colored price choice; it is never silently priced as white. Quantity and existing contact choices are reused rather than requested in a second form.
6. Opaque native raster imports no longer receive silent native approval. They reuse the existing ordinary visual-approval action with a short check for unwanted person/contact/card details. Only one front-approval button is visible while this review is pending; that same action approves the current source and advances directly to rear. Transparent native input and SVG remain on their established flow. This is **not automatic card detection**. Rear/extra-source semantic ambiguities still require human visual review.
7. Approved BM21 bitmap/material/geometry, other product geometry, optional rear, QR existing-darkest-ink logic, source/quote race protection, original assets and disabled services remain.

## Deliberately not claimed

- A source reference is not a new mockup of the selected product.
- User visual acceptance does not certify the exact physical ink count or print master.
- Whole-card wrong-brand/person-text extraction is not automatically solved. Such outputs must not be counted as successful logo extraction merely because a customer can view or approve them.
- Physical iPhone/Safari and real printing are not established by VM/native-canvas tests.
- Foreign pricing, lead/email activation and owner-account access remain separate prerequisites; no international totals or service activation were added.
- Opt-in draft replay preserves the source file but requires reference/visual acceptance again; previous acceptance and JPEG are never restored as current.
